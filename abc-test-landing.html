Topic Hub A/B/C Test

These three versions test one thing: the order the sections appear in. They come from the SEMrush suggestion to build research hubs — pages that give readers a starting point and gather everything we've published on a topic in one place, so we show up better in search and AI answers. Everything else is the same across all three: same words, same brand, same sections. So if one wins, we know the order is what made the difference.

The reasoning

Why these three orders

All three start the same way: the title, “Where Yaqeen Stands,” then Key Takeaways. Readers need their bearings first, so there's no point testing that part. What we're unsure about is what should come next. Once someone's oriented, do they want proof they can trust us, a straight answer, or the research itself? Each version answers that differently.

Version A — Framing and trust first

Vetting → Scholars → FAQ → Papers → Blogs → Videos

  • It's how the page works today.
  • Leads with our credibility — the review process and the scholars behind the work — before any answers.
  • Best for a reader who wants to know the source is trustworthy before they read anything.
  • Downside: someone who just wants a quick answer has to scroll past all of that to get to it.

Version B — Answer-first

FAQ → Papers → Blogs → Videos → Scholars → Vetting

  • Puts the answers right at the top.
  • Most people arrive with a question, so this hands it to them straight away.
  • Also helps us get quoted, since AI tools and search usually pull from the top of a page.
  • The scholars and vetting still appear, just lower down.
  • Downside: a doubtful reader sees the proof we're trustworthy later than in Version A.

Version C — Straight to the research

Papers → FAQ → Scholars → Vetting → Blogs → Videos

  • Leads with the papers themselves.
  • The whole point of a hub is to get people into the research, so this puts the destination first.
  • Best for a reader who already wants depth and doesn't need convincing.
  • Downside: anyone not ready for a full paper hits a wall of research first, so this version leans on the Key Takeaways up top to carry the short version.

Measurement

What to measure

How readers behave — the only things we track in the test:

  • How many click through to a paper or piece of content — the main outcome; the winner is decided on this.
  • How far down the page people scroll.
  • How long they actually spend reading (time on page) Leading indicator — an early signal, before the click-throughs add up.
  • How often people open the FAQ answers and the scholar bios.

Method

How to run it

Only use the split test for reader behaviour. Don't show search engines and AI tools different versions of the same page — that can get us penalised and muddies the search signals. Use the head-to-head test for how people behave; judge search and AI separately.

Check search and AI results separately. Launch the version that wins on reader behaviour.

Test integrity

What stays the same on all three

The words, the brand, the sections, and the shared opening (title → Where Yaqeen Stands → Key Takeaways). The scholar cards are identical on all three (name + title + short bio + “Author on this topic”), and how much credential and bio we show stays the opt-in, safety-driven choice we discussed.

Internal review page. When it's built for real, the winning order ships as a switch inside the website's code — not as these standalone files. These prototypes pull the real logo, fonts, scholar photos and cover images live from Yaqeen's servers, so they need an internet connection to display fully.
